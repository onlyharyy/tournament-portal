# Unwritten Rules — Tournament Portal

A Django local-first tournament portal with public registration, face-verified selfies, tournament-day face check-in, live scoring, and an admin control center.

## Local setup

```powershell
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Open `http://127.0.0.1:8000/`.

## Main flow

1. Home page shows tournament details, Live Score and Registration buttons.
2. Admin opens **Tournament Controls** to edit the name, description, venue, date, organizer, counts, poster/trophy and independently switch Registration, Live Scoreboard and Face Check-in ON/OFF.
3. Register **Teacher / Faculty** first. Their school and faculty code are stored with a verified selfie.
4. Register **Student** next. The Faculty Coordinator dropdown is filtered to the selected school.
5. The selfie must contain exactly one detectable face; the browser stores a face descriptor with the registration.
6. On tournament day, admin opens **Players / Manage Players**, starts the camera and scans a face. A matching registered student's details appear first.
7. The student presses **OKAY, I AM ARRIVED**. Only then is attendance recorded and the browser announces: `Harry from ABC School has arrived.`
8. Admin creates games, adds game descriptions, enters each player's points and remarks. The public scoreboard updates automatically.

## Face verification

The browser uses face-api.js and its model files. A local browser needs internet access the first time the models are loaded. Camera access must be allowed in Chrome/Edge.

This is a practical tournament check-in system, not a high-security biometric identity system. Keep consent, access control, retention and deletion rules appropriate for the participants.

## Automatic registration codes

Codes are generated by the application; the public forms do not ask users to type them.

- School: `KC` + sequential school number + school initials. Example: `Aditya International School` -> `KC01AIS`.
- Faculty: school code + faculty name initials. Example: Harry Prajapati -> `KC01AISHP`.
- Student: school code + faculty initials + student initials. Example: Dhaval Hada -> `KC01AISHPDH`.

The sequence increases from the highest existing school code, so deleted school numbers are not reused.

## Registration emails

After a successful registration, the participant receives an email containing their registration code and relevant registration details. The sender address is editable from Tournament Settings and defaults to `prajapatiharry198@gmail.com`.

For local development, if no SMTP password is configured, Django prints outgoing emails in the terminal. For real Gmail delivery, set the variables from `.env.example` in the environment. Use a Gmail App Password, not the normal Gmail password.
